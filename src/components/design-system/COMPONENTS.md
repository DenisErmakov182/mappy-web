## Известные несоответствия дизайн-системы, зафиксированные при переносе

Эти пункты — не ошибки переноса, а реальные пробелы/нестыковки в самой Figma-библиотеке, найденные при чтении описаний компонентов (аудит от 2026-07-18, секция «Аудит компонентов» на странице «05 · Компоненты»). Учитывать при следующем компоненте, не пытаться «улучшить» тайно мимо ADR:

- **Button**: дефолтный вариант набора в Figma — `CTA/Disabled`, поэтому новый инстанс в самой Figma вставляется неактивным. В коде дефолт сделан осознанно другим (`tone="cta"` без `disabled`) — иначе это создание невидимой ловушки для будущего использования компонента.
- **Chip**: ось `Size` в Figma содержит только одно значение `m` — размер не параметризован и в коде, до появления реальной второй величины в макете.
- **IconButton**: 36 вариантов в одном component set — выше безопасного лимита (30) по мнению самого аудита; в коде это не создало проблем (cva не ограничен так же, как Figma variants), но при добавлении новых Size/Tone в Figma стоит свериться.

## Правила (кратко, полностью — в ADR-013)

- Зависимости только вниз: atoms не знают о molecules и выше.
- Никаких магических hex/px, если есть токен из `index.css` (`@theme`-блок + `--mappy-*`).
- `Pressed` — через нативный `:active`, не JS-стейт.
- `Muted`/disabled — через нативный атрибут `disabled`, не только визуальная имитация.
- Иконки — реестр `00-foundations/Icon.tsx`, пополняется по одной, не вся Figma-библиотека разом.
- Каждый новый компонент — секция в `/components-preview` (`catalog/ComponentsPreviewPage.tsx`).
